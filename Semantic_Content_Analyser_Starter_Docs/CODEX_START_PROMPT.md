# Codex starting instructions: Semantic Content Analyser

We are starting a **new, independent Python + Hugging Face project**, provisionally called **Semantic Content Analyser**, intended both as an AI engineering learning project and a future, separately approved semantic SEO feature for SocialBuzz SEO Studio.

The project README describes the purpose, architecture, learning goals, phases, safety boundaries and first exercise. **Read README.md first and treat it as the project brief.**

## My goals

1. Learn Python-based AI engineering through real code, not just copy-pasting agent output.
2. Learn Hugging Face, embeddings, Transformer encoders, cosine similarity, TF-IDF, retrieval evaluation, FastAPI, tests, Git/GitHub and later MLOps.
3. Eventually demonstrate semantic search, internal-link opportunities and possible content overlap / pruning *review* suggestions.
4. Create a technically credible portfolio project using synthetic data, documented evaluation and reproducible code.
5. Keep it entirely separate from the running SocialBuzz codebase for now.

## What to do during this first session

- Verify my Windows / VS Code / Python / Git setup. Explain any missing prerequisites.
- Inspect the new empty folder without assuming implementation exists.
- Propose a minimal folder layout, `.gitignore`, environment setup and initial Git workflow.
- Help **me** perform selected terminal commands; explain what they do and what output to expect.
- Create only the minimal files needed for **Milestone 0** and a small **Milestone 1 embeddings demonstration** using 3 made-up SEO-themed sentences.
- Explain Python virtual environments, model downloading, tokenisation, embedding dimensions, inference and similarity in plain language.
- Ask me two or three understanding questions after the example, and let me answer before moving to the next concept.
- Show and explain code diffs; run focused checks and record the actual versions/results.
- Before any GitHub push, have me review `git status` and staged content to ensure no secrets, data or downloaded model files are included.

## Do not do yet

- No SocialBuzz integration or editing its repository/database.
- No scraping or direct contact with real client sites.
- No client uploads, private datasets, paid APIs, hosted infrastructure or production changes.
- No fast-forward to a polished dashboard, clustering, article deletion, vector database or full SEO automation.
- No public GitHub repository without my approval.
- No claim that embedding similarity proves keyword cannibalisation, ranking benefit, content quality or deletion suitability.

## How to teach

For each new skill: **explain → demonstrate a tiny example → let me try → verify → ask me to explain back → commit a working checkpoint**. Use clear terminology without hiding important technical concepts. If you write code, explain it in sections and have me edit or implement at least one small part.

## First response requested

Provide a short first-session plan, prerequisite checks, the commands I should execute myself, and the first small exercise. **Do not execute broad setup or generate all future modules before we confirm the environment.**
